One repeatable pipeline, run separately for every ICP × country: Apollo sources & qualifies → HubSpot routes & stores → Lemlist emails. New matches flow in automatically; outdated contacts drop out.

ExcludedBenelux and DACH are off-limits for any cold outreach. Because of our cooperation with Dealsuite, we never cold-email the Benelux (Belgium, Netherlands, Luxembourg) or DACH (Germany, Austria, Switzerland) regions. Do not create Apollo lists, HubSpot lists or Lemlist campaigns for these countries under any ICP.

For the maintainer — how to edit this playbook

This is a single self-contained index.html file. You are the only person who can change what everyone sees, because publishing means committing the file to the repo — which only you can do.

Easiest way — no code (Edit mode):

  1. Scroll to the bottom and click "Edit this playbook", then enter the passcode (set as EDIT_PASSCODE in the config block; currently viq-sales — change it).
  2. Click any text to rewrite it. To add a video, paste the Arcade embed link into the box that appears under each step's video.
  3. Click "Download updated file". This saves a new index.html with your changes.
  4. Publish it: replace index.html in your GitHub repo with the downloaded file (drag-and-drop in the GitHub web UI, or commit it). GitHub Pages updates the live link within a minute. See DEPLOY.md for the one-time setup.

Editing the file directly (optional):

  1. Videos: paste the Arcade embed link into the ARCADE object near the bottom, next to the matching step key (e.g. 'apollo-1').
  2. Pictures: put the image in an images/ folder next to this file and add <figure class="figure"><img src="images/your-file.png" alt=""><figcaption>Caption</figcaption></figure> inside a step, or paste a hosted image URL as the src.
  3. FAQ: copy a .faq-item block in the Questions tab and change the question/answer.
  4. Log questions instead of email: set QUESTION_ENDPOINT to a Google Form / Airtable / webhook URL.

HubSpot — route & store contacts
HubSpot is the CRM of record. You build one dynamic list per ICP × country with the right filters, then push qualified contacts from Apollo. Because the lists are dynamic, matching contacts route themselves into the correct list with no manual sorting.
4
HubSpot · Step 4
Create the ICP + country list with filters
Done ▶
What & why

Create an active (dynamic) list for the ICP + country. The fastest route is to clone an existing list that's already set up, then adapt its filters — change the ICP, the country, or both, depending on which new combination you need. Dynamic means the list re-evaluates itself — contacts are picked up or dropped as their properties change.

Watch
Key facts
ImportantThe list must be Active / dynamic, never Static. A static list won't pick up newly pushed contacts.
TipClone the closest existing list, then adapt only what differs — the ICP, the country, or both. Leave every other filter as it is.

Frequently asked
GeneralDo I run one pipeline for everything, or one per ICP and country?▶
One full pipeline per ICP × country combination. Each has its own Apollo list + workflow, its own HubSpot dynamic list, and its own Lemlist campaign. They are never merged — this keeps qualification, copy and sending volumes clean.
ApolloWhy can't I just duplicate an existing list to make a new one?▶
Duplicating a list in Apollo also copies all of its current contacts, which creates deduplication problems downstream. Always create a fresh, empty list and let the workflow populate it.
ApolloMy AI filter / workflow stopped adding contacts. Why?▶
Most often it's the Apollo plan limit. Bulk AI research and auto-add are capped by plan (Basic ≈ 100/day). Check remaining credits/limits, or run in batches of 100.
HubSpotA contact isn't showing up in the list I expected.▶
Check two things: (1) the list is Active / dynamic, not Static; (2) the contact's ICP and Country properties actually match the list filters. Those properties flow from Apollo, so fix them upstream if they're wrong.
LemlistMy email variables (name, company) are showing up blank.▶
The field wasn't mapped on import. Re-check the field mapping step — every variable used in the copy must map to a HubSpot field, including Country.
LemlistHow do I make sure someone isn't emailed by two campaigns at once?▶
Turn on "skip contacts already in another campaign" during import. This prevents double-enrolment.
